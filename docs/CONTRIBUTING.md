# Contributing to pkgwatch

pkgwatch is a static analyzer for package releases. It reads package content as hostile
input, so the safety rules below are part of the contract, not guidelines. Read them before
editing anything under `src/` or `tests/`.

> **Short version:** `uv sync` → make the change using synthetic fixtures → run all four
> gates → keep the rule catalog and changelog in sync when behavior changes.

## Non-negotiable rules

1. **Never execute package code.** No `import`, `install`, `eval`, `exec`, `subprocess` or
   build step on downloaded content — not even in tests. Extraction goes through
   `src/pkgwatch/sandbox/` only.
2. **Fixtures are synthetic and defanged.** Put them under `tests/fixtures/`, keep them as
   strings a rule can match, and keep the `HARMLESS.txt` marker in each case directory.
3. **Do not invent registry endpoints.** SPEC §3 lists the verified ones. If an endpoint is
   missing, write a `TODO` and stop.
4. **The rule engine is the only source of alerts.** Nothing outside it may raise, suppress
   or change an alert.
5. **Labels are not generated by an LLM.** Advisory-sourced exports must record provenance
   in `data/labels/PROVENANCE.md`.
6. **Spec and code disagreeing is a stop condition.** Ask instead of silently resolving it.

## Setup

Python 3.12 (`.python-version`), managed by [uv](https://docs.astral.sh/uv/):

```bash
uv sync
```

To build an installable wheel or sdist, see [BUILD.md](BUILD.md).

## Gates — run all four before opening a PR

```bash
uv run pytest -q
uv run mypy --strict src/
uv run ruff check .
uv run ruff format --check .
```

Ruff intentionally excludes `*.md` and `tests/fixtures/**` (see `pyproject.toml`). The suite
uses in-memory registry doubles — no test opens a socket. One sandbox property test is
skipped on Windows without Developer Mode; that is expected.

`main()` maps SIGINT to exit `130` and a closed stdout pipe (piping into `head`, for example) to
`0`; both entry points (`pkgwatch`, `python -m pkgwatch`) share that wrapper.
`tests/unit/test_cli_signals.py` pins the behavior.

## Common tasks

### Add a rule

A rule is a pure `DiffContext -> list[Finding]` function. To add one:

1. Add the function to the matching family module in `src/pkgwatch/rules/`. If you create a
   new module, import it in `rules/__init__.py`. **Registration order is emission order** —
   append, do not alphabetize (ruff `I001` is deliberately ignored in that file).
2. Decorate it with `@DEFAULT.register(rule_id=..., rule_version=1, severity=...,
   ecosystems=[...], families=[...], why_it_matters=..., common_benign_causes=...)`. The
   decorator requires a docstring naming what the rule detects; `rule_id` must match
   `^[A-Z][A-Z0-9_]*$`.
3. Detection literals for banned tokens (`subprocess`, `eval(`, `__import__`, ...) are built
   by concatenation, and prose is worded around them — the structural test greps for those
   spellings. `re.compile(...)` is allowed because the patterns are ours, not package data.
4. Add synthetic fixtures under `tests/fixtures/rules/<RULE_ID>/{positive,negative}/`, each
   with `old/` and `new/` trees plus a `HARMLESS.txt`. Use `registry.json` beside the trees
   only if the rule needs shipped metadata.
5. Add a parametrized test in `tests/unit/rules/` using
   `tests.support.fixtures.context_from_case` — one positive and one negative case minimum.
6. Add a row to `docs/rules.md` with columns `Rule ID | Family | Severity | Version | Detects`.
   `tests/unit/test_docs_consistency.py` checks that this table matches the live registry
   exactly, including version and severity.
7. Update `CHANGELOG.md`.

### Change a rule's detection semantics

Bump its `rule_version` in the decorator and in `docs/rules.md`. Recorded findings carry
`rule_id@rule_version`, so a bump produces new rows instead of mutating history.

### Add an ecosystem

Add a `fetch/<eco>.py` module, a spec prefix router in `cli.py`, name/version validators, a
host allowlist and digest verification, any diff tree-realignment the archive layout needs,
its rules, the report branch, and offline registry doubles for tests. The `FeedReader` /
`ArtifactSource` protocols in ARCHITECTURE §6 are a batch-path design — `ingest/` is an empty
package today, so do not build against them expecting an implementation.

### Change sandbox limits

Change the defaults in `src/pkgwatch/config.py` and the matching limits in SPEC §4, then keep
one test per rejection condition and the hypothesis property tests in sync.

## Commit style

The history uses conventional prefixes: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`,
`test:`. Milestones M1–M5 each end with a report; keep the report honest about what is
implemented versus designed.

## Known open obligations

Every report says `measured: false` — severities and weights are initial, untuned values and
detection quality has not been measured on live data. `data/labels/` ships empty, so
`data/labels/PROVENANCE.md` is still missing for advisory-sourced exports. The batch pipeline
in ARCHITECTURE §2.2 is a proposal, not a shipped command. Do not claim progress beyond M4.
